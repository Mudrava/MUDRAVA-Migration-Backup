### Воспроизведённые дефекты логики и безопасности

1. **P0 — раскрытие резервных копий на nginx/Caddy/LiteSpeed без явного deny.** `Paths::ensureStorage()` создаёт только `.htaccess` и `index.php`, а сами `.mudrava` находятся внутри публичного `wp-content`. Проверка с nginx на том же томе вернула HTTP 200 для canary. Это же относится к архивам с БД, пользователями и секретами сайта. Файл: `includes/Support/Paths.php`. До релиза требуется хранить секреты вне публичного webroot либо внедрить и проверить надёжную защиту для поддерживаемых серверов; документационное требование к администратору недостаточно для безопасного значения по умолчанию.
2. **P0 — токен восстановления даёт полный доступ к REST API администратора.** `RestoreToken::authenticate()` подменяет пользователя через глобальный `determine_current_user` без проверки активного импорта, маршрута и метода. Тест с токеном, выданным без job, получил HTTP 200 на `/wp-json/wp/v2/settings`, `/wp-json/wp/v2/users/me` и `/mudrava/v1/archives`; анонимно все три запроса возвращают 401. Файл: `includes/Http/RestoreToken.php`. Требуется ограничить полномочия ровно нужными маршрутами и job, TTL/отзыв; проверить cookie/nonce и параллельные REST-вызовы.
3. **P0 — запись вне корня через существующую временную символьную ссылку.** `WpFileTarget::beginFile()` проверяет итоговый `victim`, но открывает `victim.mudrava-tmp` без проверки, что это обычный файл внутри корня. Одноразовая проба с symlink на файл вне root изменила содержимое внешнего файла на `OVERWRITTEN`. Файл: `includes/Filesystem/WpFileTarget.php`. Требуется безопасное создание временных файлов с проверкой предков/финального inode и тест против symlink race.
4. **P0 — потеря строк при возобновлении экспорта БД.** `Exporter` сохраняет `currentTable` и `pkCursor`, но при восстановлении не восстанавливает `currentPk`. Следующий запрос идёт в режиме `LIMIT/OFFSET` с курсором PK вместо выборки `WHERE PK > cursor`. Контрактная проба с 600 строками, прерванная после первых 500, вернула архив лишь с 500 строками. Проба записана в `probes.jsonl`; нужны регрессионные тесты для разных PK и таблиц без PK. Дополнительно таблицы без PK читаются без стабильной сортировки. Файлы: `includes/Migration/Exporter.php`, `includes/Database/WpDatabaseSource.php`.
5. **P0 — отсутствует рабочий rollback при разрушительном импорте.** `RestorePoint::record()` сохраняет лишь решение и объём свободного места. Ни REST, ни UI не создают фактический архив исходного сайта и не выполняют rollback. При этом экран сообщает о возможности safety copy, а readme и `docs/recovery.md` обещают journal и откат. Файлы: `includes/Rollback/RestorePoint.php`, `includes/Http/RestApi.php`, `readme.txt`. До безопасного overwrite нужно реализовать реальную точку восстановления и проверять её до первого DROP либо убрать соответствующие обещания и вводить явный режим без восстановления.
6. **P0 — целостность архива подтверждается после записи в БД и файловую систему.** `startImport` проверяет набор частей и хвостовой маркер, но не проходит весь архив. `Importer::finish()` сверяет manifest после `DROP TABLE`, INSERT и перезаписи файлов. Повреждённый или злонамеренный архив может оставить целевой сайт разрушенным. Файлы: `includes/Http/RestApi.php`, `includes/Migration/Importer.php`. Нужна полная проверка до применения и проверка схемы/путей/ресурсов до мутаций.
7. **P1 — активный job можно заменить между тикками.** `assertNoRunningJob()` блокирует только пока `lock_until` ещё в будущем. Между тикками lock равен нулю; проба создала активный import, затем `startExportJob()` и старый import исчез. Это открывает путь к потере checkpoint и недовосстановленному сайту. Файл: `includes/Migration/JobRunner.php`.
8. **P1 — криптографическая совместимость между хостами не реализована.** Header хранит KDF, но не шифр; `cipherFromHeader()` выбирает локально доступный stack. Архив, созданный на libsodium, не может быть корректно прочитан OpenSSL-only хостом, вопреки утверждению readme. Файлы: `includes/Archive/Header.php`, `includes/Migration/JobRunner.php`. В формате нужен идентификатор алгоритма и обратная совместимость.
9. **P1 — параметрами KDF из недоверенного заголовка можно вызвать чрезмерную память/CPU.** `KeyDerivation::derive()` использует `opslimit`, `memlimit` и iterations без разумных верхних границ. Файл: `includes/Crypto/KeyDerivation.php`. Также OpenSSL GCM nonce повторяется при sequence 1 и 2^32+1 из-за усечения до 12 байт; проба это подтвердила. Для практического порога нужен расчёт, но формат обязан гарантировать уникальность или запрещать такой sequence.
10. **P1 — Auto export создаёт архив, который сам же Import UI отвергает.** Header отмечает split-mode даже когда весь архив помещается в одну часть. Проверено в браузере; Off проходит локальную проверку. Файлы: `includes/Migration/JobRunner.php`, `assets/admin.js`.
11. **P1 — большие таблицы и файлы не соответствуют заявленному bounded-memory.** `WpFileInventory::iterate()` собирает и сортирует все файлы в массиве; `Exporter` повторяет обход при resume. `RowCodec::encode()` формирует весь batch в строке, `FrameWriter` отвергает payload >256 MiB. Один BLOB/row в 10 GB, обещанный `docs/performance.md`, не поддерживается. Файлы: `includes/Filesystem/WpFileInventory.php`, `includes/Database/RowCodec.php`, `includes/Archive/FrameWriter.php`.
12. **P1 — импорт не соблюдает короткий бюджет тика для одного большого файла.** Тест с budget 10 ms и медленным FileTarget занял 233 ms и дошёл до конца, потому что остановка допускается только на `FILE_METADATA`/`DB_TABLE_BEGIN`. Это грозит таймаутом при большом файле. Файл: `includes/Migration/Importer.php`.
13. **P1 — защита загрузки и отказоустойчивость требуют усиления.** `ChunkUpload` принимает произвольные `parts`/`total` и повторно сканирует ожидаемые чанки, без лимита количества и TTL уборки; конкурентные запросы и повторные upload ID не покрыты. `JobRunner` использует неатомарную блокировку через option. Файлы: `includes/Http/ChunkUpload.php`, `includes/Migration/JobRunner.php`.
14. **P1 — документация и readme содержат недостоверные обещания.** `readme.txt` говорит о dry-run, rollback journal, push transfer, resumable upload, сохранении symlink, одной и той же памяти на 40 GB и MariaDB↔MySQL. Для части нет кода или проверки; `docs/testing.md` ссылается на несуществующий `tests/Performance`. До релиза выровнять описания с фактически проверенными возможностями.
15. **P1 — полный Plugin Check не пройден.** На ZIP 188 ERROR / 6 WARNING. Основные группы: 64 `EscapeOutput.ExceptionNotEscaped`, 26 `PreparedSQL`, 68 файловых операций, 16 i18n строк, 7 `UnescapedDBParameter`, 1 `hidden_files`, 1 `move_uploaded_file`. Нужно разбирать реальные нарушения и только узко обоснованные false positives, добиться нуля без отключения `plugin_review_phpcs`.
16. **P2 — слабая полнота i18n, сборки и CI.** POT-генератор зависит от `git ls-files` и в распакованном ZIP вывел 0 строк; оба npm-скрипта не работают. `.github/workflows/*` запускаются только вручную, а `ci.yml` исключает `plugin_review_phpcs` из Plugin Check. Нужно воспроизводимое извлечение переводов, рабочие скрипты и автоматические gate-проверки.
17. **P2 — дефекты UI и доступности.** Кнопка Download в модальном окне — `<a>` с базовым стилем WP для ссылок: синий текст и подчёркивание на тёмной кнопке, hover сохраняет несоответствие. Снимок пользователя и `export-done.png` подтверждают. Нужно проверить и исправить hover/focus/disabled для всех link-as-button, контраст, мобильный экран, фокус в модальном окне и действие после ошибок.

## Дополнительные несоответствия первоисточнику

- Нет подтверждённых релизных тестов 100 GB, 500 GB, ≥1 TB и 2 TB, ограничения памяти 64/128 MB, восстановления после kill/disk-full/DB disconnect/429/503 и матрицы хостингов. Заявление «multi-terabyte» преждевременно.
- Нет доказанного покрытия ветвей parser/state machine, интеграционных тестов REST/файловых адаптеров и security тестов. Все 127 PHPUnit тестов проходят при нескольких P0 дефектах.
- `ValueTransformer` не меняет URL в сериализованном PHP object (проба: `parseFailures=1`) и меняет byte-последовательность в бинарном значении. Для бинарного BLOB это порча данных. Требуются тесты объектов, nested serialization, JSON escaping, BLOB и нестандартных схем.
- `Logger::redact()` редактирует структурированные поля, но `detail` с текстом `password=test-secret` проходит без маски. `JobRunner` передаёт туда исходное сообщение исключения. Нужна запретная политика для raw exception text в логах.
- Не выполняется финальная проверка здоровья целевого WordPress, хотя по первоисточнику она часть критерия успешной миграции.

## Условия перехода к реализации и выпуску

Аудит завершён после сохранения этого документа и диагностических артефактов. Реализацию вести в таком порядке: (1) P0 безопасность и гарантии импорта; (2) корректность формата/resume и регрессионные тесты; (3) производительность и реальные предельные тесты; (4) UI/i18n/readme; (5) полный Plugin Check и CI; (6) браузерные сценарии на релизном ZIP. Каждую исправленную ошибку закрывать воспроизводимым тестом и повторной проверкой в Chrome пользователя. Публикация WordPress.org остаётся отдельным финальным шагом после нулевых замечаний и ручной проверки правил.
